## 4. Network Delivery, Caching & Compression Audit

1. **Static Asset Caching**:
   - `express.static` in `backend/server.js` was registered with default parameters:
     ```js
     app.use(express.static(path.join(__dirname, '../frontend/public')));
     ```
   - Measured response headers for `/assets/js/app.js`:
     - `Cache-Control: public, max-age=0` (Forces browser revalidation on every session).
     - `Content-Encoding: undefined` (Uncompressed 634 KB transfer).
2. **Dynamic Compression**:
   - GZIP response middleware in `server.js` only overrides `res.send()` for route handlers. Static file streaming (`send` package inside `express.static`) bypasses `res.send()`, so static CSS, JS, and SVG files are transmitted completely uncompressed.

## 5. Backend Database & Query Architecture Audit

### In-Memory Collection Loads & JS-Side Filtering ($O(N)$ Memory Bottlenecks)
The audit identified at least 14 critical endpoints that load entire database collections into Node.js heap memory before filtering or paginating:
1. `GET /api/admin/users`: `await db.users.find()` loads all users into memory, followed by JavaScript `.filter()` on `role`, `status`, `search`, and `.slice()` for pagination.
2. `GET /api/admin/visa/applications`: `await db.visaApplications.find()` loads all applications into memory, followed by JavaScript `.filter()` on `status` and `search`.
3. `GET /api/admin/tourism/bookings`: `await db.tourBookings.find()` loads all bookings into memory, followed by JavaScript `.filter()` on `status` and `search`.
4. `GET /api/admin/payments`: `await db.payments.find()` loads all payment records into memory, followed by JavaScript `.filter()` on `status`.
5. `GET /api/admin/support/tickets`: `await db.supportTickets.find()` loads all tickets into memory, followed by JavaScript `.filter()`.
6. `GET /api/admin/inquiries`: `await db.contactInquiries.find()` loads all inquiries into memory before slicing.
7. `GET /api/admin/notifications`: `await db.notifications.find()` loads all notifications into memory before filtering.
8. `GET /api/admin/audit-logs`: `await db.auditLogs.find()` loads all audit logs into memory before filtering.
9. `GET /sitemap.xml`: fetches all packages and visas into memory to generate URLs.
10. `GET /api/reviews`: `await db.reviews.find()` loads all reviews and sorts via JavaScript `.sort()`.
11. `ChatbotService.processMessage`: `await db.chatMessages.find({ conversationId })` retrieves all messages in a conversation history, sorts in JS memory, and slices the last 12.

### MongoDB Index Audit
- **Collections with existing compound indexes**: `AuditLog`, `ChatConversation`, `ChatMessage`, `Notification`, `TourBooking`, `TourPackage`, `VisaApplication`.
- **Collections lacking required query indexes**:
  - `Payment`: No compound index on `{ userId: 1, createdAt: -1 }` or `{ providerOrderId: 1, status: 1 }`.
  - `SupportTicket`: No index on `{ ticketNumber: 1 }` or compound index on `{ userId: 1, status: 1, createdAt: -1 }`.
  - `Refund`: No compound index on `{ paymentId: 1, status: 1 }` or `{ userId: 1, createdAt: -1 }`.
  - `PaymentEvent`: No index on `{ eventId: 1 }` or `{ providerOrderId: 1 }`.
  - `CustomerProfile`: No index on `{ userId: 1 }`.
  - `VisaDocument`: No compound index on `{ applicationId: 1, status: 1 }`.
